# Codex Desktop writer locks have no guaranteed idle release deadline

Research for [Agent Bridge #214](https://github.com/firejune/AgentBridge/issues/214), 2026-11-22.

Desktop build 29803 can unsubscribe an inactive ordinary thread without a model turn, and successful persistence shutdown releases the writer. A Desktop snapshot found 68 locked threads, many still listed in the sidebar, with about 16 hours since the oldest rollout write. The sampled Desktop-owned server exposed no external endpoint for `archive --remote`. The queued self-archive in #211 demonstrated a Desktop archive on the exact same thread in one model turn. Agent Bridge implementation is pending in open PR #215.

## Version and evidence

- **Installed macOS Desktop.** The bundle plist reports version `26.1117.41037`, build `29803`. Independent inspection reported that bundled `codex --version`, run with a temporary `CODEX_HOME`, returned `codex-cli 0.171.0-alpha.13`. Bundled help listed WebSocket and Unix forms for archive's `--remote` and stdio as the app-server default.
- **Public Rust source.** OpenAI's annotated tag `rust-v0.171.0-alpha.13` has tag object `e0fd22a0e4e047a795d4bfa2b135fd3e6356eef2` and peels to commit `581161ab41e643d942e1e1b5f561034060bf18e3`. All source line links below use that commit. The matching CLI version supports the comparison. The installed executable's exact compiled commit and Desktop-specific patches remain unverified. [OpenAI release, published Nov 18 UTC][release] · [Tagged source tree][tree]
- **Desktop evidence.** The Electron code and process observations below come from the operator's installed-bundle inspection. The separate runtime probe ran the bundled binary with an isolated home. The Desktop snapshot records writer-lock and sidebar retention, and #211 records an observed Desktop archive. The end-to-end Desktop idle scheduler and externally callable IPC remain unverified.

## Acquisition and release

The local thread store acquires the writer guard when creating or resuming a persistent thread and keeps it with the live rollout recorder. The coordinator uses an exclusive nonblocking file lock on `${CODEX_HOME}/thread-writer-locks/<thread-id>.lock`. A contending acquisition maps to a thread-store conflict and, on the archive path, to JSON-RPC invalid request `-32600` with the active-writer message. [Create and resume][live-open] · [Recorder registration][live-resume] · [Lock implementation][lock] · [Conflict mapping][conflict] · [Archive error mapping][archive-error] · [RPC error code][rpc-code]

On orderly thread shutdown, core requests persistence shutdown. The rollout recorder drains pending writes and waits for its writer task to exit, and the local store removes its live recorder entry. The final writer guard drop closes the lock descriptor. Lock-file cleanup is best effort under the coordination lock, so pathname presence alone cannot establish current ownership. Core can signal shutdown completion after logging a persistence error, so treat an unload notification as lifecycle evidence and successful persistence shutdown as the release condition. [Core shutdown][core-shutdown] · [Recorder drain][recorder-shutdown] · [Local recorder removal][store-shutdown] · [Guard drop][guard-drop]

Issue #214 records 68 matching lock and rollout descriptors and a nonblocking shared-lock probe that returned `EWOULDBLOCK`. The later redacted process sample found 70 matching pairs in the Desktop-owned app-server child. The counts are from separate snapshots. The later sample did not open a live lock. [Issue observation](https://github.com/firejune/AgentBridge/issues/214)

## Unsubscribe and idle unload

1. **Desktop decides when to unsubscribe.** The read-only ASAR inspection parsed the Electron header and then the packed JS member `.vite/build/app-server-host.js` (SHA-256 prefix `ebdda7f51f6d1c28`). At member byte offsets `1744900–1751300`, the inactive-owner scheduler requires a resumed thread, a local history subscription, and no active view. Exemptions include an active runtime, a qualifying in-progress turn, unreceived steering, and an empty thread that has yet to persist. Its TTL is `108e5` ms (180 minutes). When more than ten eligible inactive non-ephemeral threads accumulate, it selects the earliest excess immediately. It calls the unsubscribe helper, marks the thread `needs_resume`, and clears local stream ownership. The helper near byte offset `1074181` sends `thread/unsubscribe`. These offsets are relative to the packed member bytes.
2. **The server decides when to unload.** `thread/unsubscribe` removes only the requesting connection's subscription. A disconnect also removes that connection's subscriptions. The timer is armed when the thread is inactive and has zero subscribers. Its deadline is the configured delay after the later of those transitions, and observed thread activity can reset the inactivity timestamp. The tagged default is 60 seconds via `thread_unload_delay_secs`. Normal teardown awaits runtime shutdown, removes the loaded runtime and status, and emits `thread/closed`. Slow idle shutdown logs a warning after ten seconds and keeps waiting. [Unsubscribe handler][unsubscribe] · [Connection cleanup][connections] · [Timer][timer] · [Default configuration][default-delay] · [Idle teardown][idle-shutdown] · [OpenAI app-server guide][guide-unsubscribe]

   **Desktop observation.** At 18:04 KST on 2026-11-22, an operator session observed 68 Desktop threads with writer locks. The earliest rollout last-write time was 01:45 KST that day, about 16 hours before the snapshot. Many of the locked threads still appeared in the sidebar. A rollout's last-write time measures time since the last recorded write. The server's inactivity clock depends on runtime activity and subscription state. Sidebar retention of a subscription is a hypothesis. The observed locks and sidebar listings show that elapsed time since the last write gives no guaranteed idle release deadline.

3. **The bundled binary exercised the no-turn path in isolation.** The operator set `thread_unload_delay_secs = 2` in a temporary `HOME` and `CODEX_HOME`, initialized a stdio app server, and called `thread/start` without starting a model turn. The thread was loaded and its lock path existed. `thread/unsubscribe` returned `unsubscribed` while the path still existed. At 2.00 s the probe received `thread/closed`, the path was absent, and the thread was no longer loaded. The child exited 0 and the scratch home was removed. This checks the bundled app server with a controlled subscription and delay.

The tagged public client-request registry exposes `thread/unsubscribe`. It has no `thread/unload`, `thread/close`, or `thread/stop` request, and `thread/closed` is a server notification. An independent client connected to the same server can drop its own subscription only. In the inspected Desktop JS, `thread/unload` was absent across packed JS. In `.vite/build/app-server-host.js`, `thread/stop` appears in the durable/Aeon branch near member offsets `2237275` and `2278750` and is invoked as an extension in early bootstrap near `4550759`. Ordinary handling uses unsubscribe or interrupt as appropriate. The durable extension's lock effects and external reachability remain unverified. [Public request registry][requests] · [Closed notification][closed] · [Subscription ownership][subscription-ownership]

## Remote archive and the sampled Desktop owner

The tagged CLI accepts `codex archive --remote <addr> <session>`. It connects to the explicitly selected app server and sends `thread/archive` after target resolution. The address parser accepts `ws://host:port`, `wss://host:port`, `unix://PATH`, and bare `unix://`, which resolves to the default app-server control socket. These address forms select a server transport. They provide no address for an existing private stdio connection. [Archive CLI flags][archive-flags] · [Endpoint routing][cli-route] · [Address parser][address] · [Client connection][remote-connect] · [Archive RPC][archive-rpc]

The owning server's archive handler can shut down its own loaded runtime before archiving. It prepares the root and spawned descendants for removal, stops any eligible runtime in its thread manager, then calls the store. The store requires writer ownership across the relevant subtree before moving rollout files into `archived_sessions` and updating archive metadata where SQLite is present. A separate app server sharing the same Codex home cannot shut down the owner's runtime from its own thread manager. If the other process still owns the writer guard, storage refuses the operation. A shutdown failure or timeout on the owning server also leaves the store's writer check in force. Archive changes persisted archive state in addition to unloading any local runtime. Tagged upstream tests cover archiving a newly started thread through its owner with zero turns, and refusal before file moves when another store holds a descendant's writer. [Archive preparation][archive-prepare] · [Archive handler][archive-handler] · [Local store locking][archive-locks] · [Rollout and metadata changes][archive-move] · [Owner integration test][owner-test] · [Contending-store test][conflict-test]

The operator verified both paths with two loopback TCP WebSocket app servers from the bundled CLI, sharing a temporary `HOME` and `CODEX_HOME`. With no model turn, the owner started, archived to materialize, unarchived, and resumed a throwaway thread. Its loaded list included the thread and the other server's did not. Raw `thread/archive` against the other server returned `-32600` with the exact active-writer detail. `codex archive --remote` against the owner exited 0, reported `Archived session`, moved the rollout into `archived_sessions`, and left the thread absent from the owner's loaded list. Both server children stopped and the scratch home was removed. The successful remote path used an explicitly configured listener on the owner.

In the later installed-process sample, the Desktop-owned app-server child had no `--listen` argument. Structured `lsof -nP -p PID -FfPtnT` output showed connected Unix peers on FDs 0, 1, and 2. All nine Unix FDs had peers, with zero pathname Unix listeners and zero TCP listeners. Outbound IPv4 was present. The tagged CLI defaults to stdio, which is consistent with this sample. The sampled owner exposed no listener that `archive --remote` could address. A different daemon, including one on the default control socket, would only archive through its own runtime and store. The sample does not establish transport behavior for other Desktop versions or launch modes. [App-server listen flag][listen] · [Default transport][transport]

The installed `.vite/build/early-bootstrap-916-90e0adb52d70fbc5.js` member (SHA-256 prefix `1054c85006a5740e`) shows native archive preparation through Desktop's app-server connection near byte `3190712`, and the Desktop manager's `thread/archive` request near byte `1439449`. These internal handlers establish a Desktop-owned route to archive. No supported externally callable IPC endpoint for ordinary-thread unload or writer release was found.

Agent Bridge recognizes the exact `-32600` active-writer reply and labels the affected route close `desktop_holds_thread`. The recommended path is #211's queued self-archive on the exact same Desktop thread. The issue records one model turn and confirms the archive through both the rollout move and the thread's removal from the sidebar. Open PR #215 implements the Agent Bridge path and reports a successful scratch CLI run. Its close flow keeps the route pending until archive is independently confirmed and does not resend an accepted entry. ## Remaining gaps

- Exact installed Rust build commit, effective Desktop server unload delay, and elapsed time from a Desktop view becoming inactive to actual writer release. Whether sidebar-listed threads retain a subscription remains unverified.
- Whether another supported Desktop action requests an ordinary unsubscribe and what the durable/Aeon `thread/stop` extension does to writer ownership.
- A supported externally addressable app-server endpoint for the Desktop-owned process. The isolated remote test used an explicit loopback listener. Remote archive against the Desktop-owned server remains untested.
- Merge and deployment of the Agent Bridge queued self-archive implementation in PR #215.
